# pump.fun 확장 — 되나, 기존 메소드가 얼마나 옮겨지나

2026-09-25 타당성 평가. 코드는 아직 없다. 이 문서는 "가자/말자"를 결정하기 위한
근거이고, 결론은 **갈 수 있지만 기존 메소드를 그대로 적용하는 것은 아니다**이다.

## 한 줄 결론

옮겨지는 것은 **프레임**(제안 → 협의회 → 제약 → 페이퍼 장부 → 실현수익 귀속)과
**검증 규율**(비용 차감 백테스트·블록 부트스트랩·다중검정 보정·디플레이티드 샤프)이다.
옮겨지지 않는 것은 **모델 자체**(일봉 HMM 레짐·GARCH·60일 위험조정 모멘텀)다. 이
시장에서 돈은 "어느 코인을 고르나"보다 "언제 참가하지 않나"(레짐)와 "집행 비용을
넘기는가"에서 결정된다 — 그리고 우리 도구가 가장 잘하는 게 바로 그 두 질문이다.

## 왜 모델이 그대로 안 옮겨지나

| | Upbit 알트 (지금) | pump.fun |
|---|---|---|
| 데이터 해상도 | 일봉 350일, HMM 적합 창 120일 | 초·분 단위. 토큰 수명이 분~시간이라 **토큰별 시계열 모델은 성립 불가** |
| 유니버스 | 메이저 + 상위 30 + 보유분 | 하루 수천~수만 개 신규 생성. 다중검정이 30배가 아니라 1,000배 |
| 가격 형성 | 호가창 | **결정론적 본딩커브**(가상 준비금 x·y=k). 슬리피지가 가정이 아니라 수식으로 계산된다 |
| 편도 비용 | 수수료 0.05% + 슬리피지 0.05% | 커브 위 1.25% + 우선순위 수수료/Jito 팁 + MEV 샌드위치. 졸업 후 PumpSwap 0.25%. **왕복 3~5%가 보통** |
| 기저율 | 대부분 코인이 살아 있다 | 졸업(커브 완료 → AMM 이주)률 **0.2~0.6%**(2025~26). 거의 전부 0으로 간다. 수익은 극단적 우측 꼬리 |
| 상대 | 다른 트레이더 | 번들러·스나이퍼·개발자 덤프·러그. **우리를 노리는** 적대적 환경 |
| 자본·집행 | KRW 계좌, REST 주문 | SOL 지갑, 온체인 서명. 블록 400ms, Railway에서 스나이핑 지연 경쟁은 불가능 |

## 무엇이 어떻게 옮겨지나 (기존 메소드 → pump.fun 대응)

1. **제어 평면** — 새 엔진이 아니라 **새 장부(venue)**. 타깃 `market`에 `PF:<mint>` 네임스페이스,
   상태 파일 `data/control/state-pumpfun.json`을 따로 열고(지금 paper/real을 나누듯), 별도 킬스위치,
   총노출 상한은 **전체 에쿼티의 2% 이하**로 정책에 박는다. Upbit 장부와 섞이면 귀속이 오염된다.
2. **페이퍼 장부** — 필수 1단계. 단 체결 시뮬은 상수 슬리피지 0.05%가 아니라 **본딩커브 수식으로**
   (주문 크기 → 가상 준비금 이동 → 체결 평균가) + 우선순위 수수료 + 블록 지연(신호 시점이 아니라
   N블록 뒤 커브 상태로 체결). 이걸 안 하면 페이퍼 기록이 자기기만이다 — README의 원칙 그대로.
3. **HMM 레짐** — 토큰별로는 못 쓴다. **시장 레짐**으로 쓴다: 일별 (신규 생성 수, 졸업 수, 졸업률,
   SOL 수익률, 졸업 토큰의 24h 생존율) 시리즈에 3상태 HMM → "참가 / 축소 / 비참가" 게이트.
   2026년 상반기에 졸업률이 3배 떨어진 것처럼 이 시장은 **레짐이 지배적**이다.
4. **GARCH** — 토큰별 X. SOL 조건부 변동성으로 총노출 축소 정도만.
5. **모멘텀 팩터 → 커브 진행 팩터** — 20/60일 수익률 대신 SOL 유입 속도, 고유 매수 지갑 수, 매수/매도
   비율, 개발자 지갑 잔여 비중, 상위 10 홀더 집중도, 창설 블록 번들 매수 여부, creator의 과거 토큰 이력.
   "헤드라인이 아니라 바이트코드를 읽는다"(`docs/onchain-contracts.md`)의 pump.fun 판은
   **홀더 분포와 creator 이력**이다. mint/freeze 권한은 pump.fun이 기본으로 회수하므로 EVM식
   셀렉터 분석은 대상이 없고, 리스크는 계약이 아니라 사람(개발자 덤프)에게 있다.
6. **Kelly 사이징** — 쓸 수 있으나 승률 한 자릿수 %·비대칭 payoff라 ¼ Kelly + 포지션당 절대 상한.
   "이 포지션은 0이 된다"가 기본 가정.
7. **블록 부트스트랩·Bonferroni·DSR·SPA** — **가장 잘 옮겨지는 부분**. 유니버스가 수천이라 백테스트
   수익의 거의 전부가 스누핑이다. 검정 단위는 시간이 아니라 **사건(토큰)** — `onchain/event-study.ts`의
   사건 단위 부트스트랩을 그대로 쓴다.
8. **기대 엣지 게이트**(`control/edge.ts`) — 편도 비용을 0.1%가 아니라 실측 2%대로 넣으면 결정
   대부분이 "안 함"으로 나온다. 그게 맞는 답이다.
9. **협의회** — 리스크 총괄 거부권에 온체인 항목 추가(creator 러그 이력, 번들 매수, 상위 10 홀더
   ≥ X%). 센티먼트 총괄은 텔레그램/X 존재 여부 정도로 축소.

## 돈이 될 수 있는 전략 후보 — 정직한 순서

- **A. 졸업 직후 모멘텀(post-migration).** 커브 위가 아니라 PumpSwap 이주 후 첫 N분의 유동성·홀더
  증가·매수 비율로 진입, 시간/손절 규칙으로 청산. 경쟁이 덜하고(스나이퍼는 이미 빠졌다), 데이터가
  있고(이주 이벤트는 무료 스트림), 비용이 낮다(0.25%). 첫 후보.
- **B. 커브 후반 진입(약 60~85 SOL 구간).** 졸업 확률이 급격히 오르는 구간. 커브가 결정론적이라 졸업
  실패 시에도 되팔 수 있어 손실이 유한하다. 텔레그램 채널 유무만으로 졸업률이 약 9배 갈린다는 관측
  (SSRN 2026, 832,941 런치)처럼 **관측 가능한 피처가 있는** 전략.
- **하지 말 것.** 창설 직후 스나이핑(봇·번들러와 밀리초 지연 경쟁, 우리 인프라로 불가능). 토큰을 직접
  만들어 creator fee를 버는 것(펌프앤덤프와 구분되지 않고 법적 리스크). 두 가지 다 이 저장소의 "근거
  있는 결정" 원칙과 맞지 않는다.

## 인프라

- **데이터.** PumpPortal WebSocket(`wss://pumpportal.fun/api/data`) — 신규 토큰·이주 스트림은 무료,
  토큰별 트레이드 스트림은 유료(0.01 SOL / 1만 메시지). 또는 Helius·QuickNode RPC로 프로그램
  `6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P` 로그를 직접 디코딩. 과거 데이터(백테스트)는 Bitquery.
  `onchain/rpc.ts`의 규율(전역 토큰버킷, 실패 이유 기록)을 Solana RPC 클라이언트에 그대로.
- **집행.** `@solana/web3.js` + 서버 보관 서명 키(금고 AES-256-GCM, `docs/accounts.md`) 또는 PumpPortal
  trade API(추가 0.5%). 기존 거래소 고정 IP 프록시는 무관하다.
- **자본.** Upbit → SOL 출금 → 전용 지갑. 트래블룰·출금 한도 확인. 장부 단위는 KRW가 아니라 **SOL**,
  KRW 환산은 표시용.
- **지연.** Railway ↔ Solana 블록 400ms. 분 단위 전략(A·B)만 가능하다는 뜻이고, 그래서 A·B를 골랐다.

## 리스크 — "리스크는 있지만"을 구체적으로

- 포지션 전손이 기본값. 러그·개발자 덤프·유동성 증발. honeypot은 드물다(권한 회수) 대신 덤프가 흔하다.
- MEV 샌드위치. 슬리피지 허용치가 곧 뺏기는 돈이라 낮게, 대신 미체결을 감수.
- 법·세금. 한국 거주자의 해외 DEX 거래·가상자산 과세는 세무 확인 대상. 토큰 창설·마케팅은 하지 않는다.
- 운영. 서버에 개인키. 지갑에는 그 주의 한도만 넣는다.
- 기대치. 이 시스템의 Upbit 로테이션조차 SPA p=0.33, 파라미터 격자 전부 음수였다(`docs/library-survey.md`).
  pump.fun은 그보다 어렵다. 도구가 답하는 것은 "우리에게 엣지가 있나"이고, 답이 "없다"여도 도구는 제 일을
  한 것이다.

## 단계 (제안)

0. 이 문서 → **갈지 말지 결정** (owner).
1. **관측 전용** (1~2주, 비용 0). PumpPortal 신규·이주 스트림 구독 → `data/pumpfun/*.jsonl`에 생성·이주·
   이주 후 5/30/120분 가격을 기록. `/pumpfun` 읽기 전용 화면. 장부·제어 평면 안 건드림.
2. **사건 백테스트.** 1의 축적분 + Bitquery 과거로 전략 A·B를 본딩커브 체결 시뮬·실비용으로 돌리고,
   사건 부트스트랩·유니버스 크기 Bonferroni·DSR. **여기서 통과 못 하면 끝** — 그게 정상 결과일 확률이 높다.
3. **페이퍼 장부**(SOL 단위) + 제어 평면 venue 분리 + 리스크 총괄 온체인 거부권 + `/pumpfun` 장부 화면.
4. **실돈.** 전용 지갑, 전체 에쿼티 2% 이하, 설정 페이지 "REAL" 타이핑과 같은 절차, 일 손실 20%면
   자동 정지. 2·3의 실기록이 양수일 때만.
