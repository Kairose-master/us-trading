# 파이프라인 품질·위험 노드 (2026-09-07)

## 참고한 검증 가능한 설계

- [Microsoft Qlib](https://github.com/microsoft/qlib): 데이터 처리, 모델, 포트폴리오와 평가를 구분하는 연구 워크플로. 입력 검증을 알파 계산 앞에 둔다.
- [QuantConnect LEAN Algorithm Framework](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/overview): Alpha → Portfolio Construction → Risk Management → Execution 분리. 본 구현도 공개 목표 비중이 리스크 관문을 우회하지 못하게 한다.
- [LEAN Reality Modeling](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/key-concepts): 호가·체결·거래비용을 고려해야 한다. 관측 호가가 없으면 스프레드를 0으로 가정하지 않고 제안을 보류한다.

위 프로젝트의 설계를 참고한 TypeScript 구현이다. 라이브러리를 직접 통합하거나 해당 프로젝트가 이 전략의 수익성을 검증했다는 의미가 아니다.

## 추가된 실제 처리 노드

| 노드 | 입력 → 출력 | 정책 |
|---|---|---|
| data-quality | 틱 → 유효 틱 또는 거부 사유 | 유한 양수 가격, 비음수 시장 데이터, 정상 호가, 선택적 소스 시각·순서 검증; replay 제외 |
| signal-eligibility | 앙상블 + 시세 이력 → 적격 알파 | 유효 틱 21개, 최근 시세 120초 이내 |
| risk-allocation | 적격 알파 + 변동성 → 초안 비중 | 양의 알파 × 신뢰도 / max(틱 변동성%, 0.05), 종목별 컨텍스트 상한, 총노출 90% 이하 |
| tradability-gate | 초안 비중 + 호가 + 리스크 컨텍스트 → 공개 목표 | 양방향 호가·수량 필수, 스프레드 50bps 이하, 기존 riskCheck 통과 |

각 노드는 실제 처리량·지연과 샘플을 기존 `/pipeline` 그래프와 노드 상세 API로 제공한다. 거래 가능성에서 거부한 종목은 실행용 내부 목표를 동결하고 공개 `portfolioTargets`에서는 제외한다. 제어 평면은 통과한 목표만 읽는다. 기존 다른 매니저의 제안과 보유 유지 정책은 그대로 적용된다. 전 종목 보류는 새 제안을 만들지 않으며 기존 제어 평면 제안을 취소하는 기능은 아니다.

시세가 끊기면 새 이벤트가 없어도 공개 목표 getter가 만료된 종목을 제외한다. 잘못된 새 틱은 기존 목표를 철회한다. 중복·역순 이벤트와 과거 재생은 현재 정상 시세를 훼손하지 않는다. 뉴스는 심볼+ID 중복 제거, Mock 제외, 발행 후 6시간 TTL; 감성 알파도 6시간 후 앙상블에서 제외한다. 멈춘 노드의 10초 처리량은 실제로 0까지 내려간다.

## 운영상 의미와 한계

- 정책은 `backend/src/pipeline/guards.ts`의 `POLICY`에서 확인한다. 수익 최적화로 추정한 값이 아니라 보수적인 초기 운영 기준이다.
- Yahoo처럼 호가 수량이 없는 소스는 피처 계산·관측은 계속하지만 신규 목표를 내지 않는다. 거래용으로 사용하려면 실제 호가 공급이 필요하다.
- `observedAt`이 없는 기존 틱 어댑터는 수신 시각 기준이다. 공급자가 지연된 가격을 반복 전송하는 경우까지 식별할 수는 없다. Upbit 라이브 틱은 공급자 timestamp를 전달하며 120초 신선도와 단조 증가를 검사한다.
- 틱 간격은 일정하지 않으므로 역변동성은 연율 목표 변동성이나 공분산 최적화가 아니다. 상한을 넘는 몫은 재배분하지 않아 현금으로 남는다.
- 재생 분봉은 라이브 틱과 주기가 달라 워밍업에도 섞지 않는다. 장애 후 21개의 정상 틱이 확보되어야 처음 신호가 나온다.
- 스프레드 관문은 기대 수익 추정이나 비용 차감 백테스트가 아니다. 기존 비용 모델·워크포워드 평가와 페이퍼 실적을 별도로 확인해야 한다. 수익률 개선을 주장하지 않는다.
- 주문·자동운행·실거래 환경변수는 변경하지 않는다. main은 자동 배포되므로 변경은 검토용 브랜치/PR로 전달한다.

## 검증

`npm run check --prefix backend`: 타입 검사와 전체 테스트. 새 회귀 테스트는 워밍업, 가격 오염, 무이벤트 만료, 재생 차단, 호가/스프레드/리스크 차단, 뉴스 중복, DAG 순환, 배분 상한을 확인한다.
